## 최근 실무 워치리스트

### 1. SageMaker Inference의 Multi-Instance GPU 지원

- **핵심:** AWS가 SageMaker 실시간 추론 엔드포인트에서 NVIDIA MIG 기반 GPU 파티셔닝을 지원한다. 여러 모델을 하드웨어 격리된 GPU 조각에 배치할 수 있다.
- **왜 중요한가:** 소형·중형 모델, 임베딩·리랭커·가드레일 모델을 GPU 한 장씩 할당하던 낭비를 줄이고, 테넌트 간 지연 간섭을 낮출 수 있다.
- **바로 해볼 것:** 모델 가중치뿐 아니라 KV cache, 최대 컨텍스트, 동시성, 런타임 오버헤드까지 합산해 필요한 MIG 프로파일을 산정한다. AWS 예제 노트북으로 기존 whole-GPU 엔드포인트와 p95/p99·TTFT·토큰당 비용을 비교한다.
- **주의:** 비동기·서버리스 엔드포인트는 대상이 아니며, GPU 인스턴스 전체 비용은 계속 청구된다.
- **원문:** [AWS — SageMaker Inference Multi-Instance GPU](https://aws.amazon.com/blogs/machine-learning/sagemaker-inference-now-supports-multi-instance-gpu-to-maximize-gpu-utilization-for-model-endpoints/) (2026-11-06)

### 2. 메타데이터 기반 서버리스 MCP 데이터 레이크 접근

- **핵심:** AWS가 ECS Fargate에서 서버리스 MCP 서버를 운영하고 JSON 메타데이터로 데이터셋을 노출하는 패턴을 공개했다.
- **왜 중요한가:** 데이터셋마다 개별 에이전트 통합 코드를 만들지 않고도 도구 인터페이스를 표준화할 수 있다.
- **바로 해볼 것:** 개발용 데이터 레이크 한 개를 대상으로 read-only 도구만 노출하고, 스키마 검증·타임아웃·행 수 제한·감사 로그를 추가한다. 프롬프트 인젝션이 쿼리 범위를 넓히지 못하도록 권한을 서버에서 강제한다.
- **원문:** [AWS — Serverless MCP server on ECS Fargate](https://aws.amazon.com/blogs/machine-learning/serverless-mcp-server-for-ai-agent-data-lake-access-on-amazon-ecs-fargate/) (2026-11-06)

### 3. 에이전트 권한을 사용자 권한과 분리해 통제

- **핵심:** AWS와 Okta 예시는 AgentCore Gateway를 단일 진입점으로 두고, 사용자 위임과 에이전트·도구 권한을 Cedar 정책으로 결합한다.
- **왜 중요한가:** OAuth 토큰이 있다는 사실만으로 에이전트가 사용자의 모든 권한을 행사하게 하면 blast radius가 지나치게 커진다.
- **바로 해볼 것:** `user × agent × tool × resource` 권한 행렬을 만들고, allow/deny 결정과 도구 호출을 동일 trace ID로 기록한다. 토큰 발급 후 권한 회수 지연도 테스트한다.
- **원문:** [AWS — Govern AI agent access with Okta and AgentCore](https://aws.amazon.com/blogs/machine-learning/govern-ai-agent-access-with-okta-cross-app-access-and-amazon-bedrock-agentcore-part-2/) (2026-11-06)

### 4. 원격 코딩 에이전트의 격리 실행과 PR 기반 승인

- **핵심:** AWS는 Claude Code 작업별로 격리된 원격 세션을 만들고, 모델 호출을 Bedrock으로 통제하며, 결과를 GitHub PR로 돌려주는 패턴을 소개했다.
- **왜 중요한가:** 장시간 코딩 에이전트를 로컬 개발자 권한에서 분리하고, 변경 검토·감사·비용 추적의 경계를 명확히 할 수 있다.
- **바로 해볼 것:** 세션별 임시 자격 증명, 네트워크 allowlist, 비밀정보 마스킹, 최대 실행시간과 비용 한도를 설정한다. main 직접 push를 금지하고 필수 CI와 CODEOWNERS 승인을 적용한다.
- **원문:** [AWS — Remote Claude Code sessions on AgentCore](https://aws.amazon.com/blogs/machine-learning/extend-claude-code-to-remote-sessions-on-amazon-bedrock-agentcore-with-security-controls/) (2026-11-06)

### 5. 운영 중 에이전트 실패를 회귀 테스트로 전환

- **핵심:** NVIDIA는 실제 에이전트 실행의 실패 증거를 우선순위 이슈와 맞춤 평가로 변환하고, 프롬프트·도구·메모리·스킬·하네스를 개선하는 루프를 제안한다.
- **왜 중요한가:** 단발성 데모 평가보다 운영 trace에서 반복되는 실패를 자동 회귀 테스트로 축적하는 편이 신뢰성 향상에 직접적이다.
- **바로 해볼 것:** 실패 trace에서 입력, 도구 결과, 기대 행동, 금지 행동을 분리해 eval fixture로 저장한다. 수정 전후 task success, tool-call 수, 토큰, 지연시간, 비용을 함께 비교한다.
- **원문:** [NVIDIA — Turn Agent Failures into Tests and Harness Fixes](https://developer.nvidia.com/blog/use-nvidia-nemo-to-turn-agent-failures-into-tests-and-harness-fixes/) (2026-11-04)
