## 1. ChatGPT Wallet: agent 결제와 실제 카드 정보 분리

- **핵심:** 사용자가 저장한 적격 카드를 agent가 직접 보지 않도록 대체 결제 credential을 사용하고, 결제 직전 merchant·상품·총액·카드를 사용자가 검토한 뒤 biometric으로 승인한다.
- **왜 중요한가:** agentic commerce에서 모델에게 결제 credential을 제공하지 않으면서도 구매 실행을 허용하는 tokenization·human approval 패턴이다.
- **바로 해볼 것:** 결제 전 immutable order summary, 금액·merchant allowlist, 1회성 payment token, biometric confirmation, idempotency key와 merchant confirmation 확인을 구현한다.
- **주의:** 사용자의 승인만으로 주문 성공을 간주하지 말고 merchant의 최종 confirmation을 별도 확인해야 한다. 초기 제공 범위는 미국의 일부 성인 Pro 사용자와 적격 카드로 제한된다.
- **원문:** [OpenAI — ChatGPT Wallet](https://openai.com/products/release-notes/)

## 2. production inference 데이터 기반 model improvement flywheel

- **핵심:** SageMaker HyperPod Data Capture가 실시간 inference 입력·출력을 S3에 독립적인 세 단계로 기록해 drift·실패 패턴·재학습 데이터를 만들 수 있게 한다.
- **왜 중요한가:** 사전 curated dataset은 domain jargon, 새로운 형식과 사용자 행동 변화를 포괄하지 못한다. 운영 데이터가 없으면 품질 하락 원인을 추적하거나 개선 dataset을 만들기 어렵다.
- **바로 해볼 것:** 원문을 무조건 저장하지 말고 PII redaction, sampling, consent, retention을 먼저 정의한다. capture → failure clustering → human labeling → fine-tuning → shadow eval → canary의 폐쇄 루프를 만든다.
- **원문:** [AWS — Model improvement flywheel with HyperPod Data Capture](https://aws.amazon.com/blogs/machine-learning/build-a-model-improvement-flywheel-with-amazon-sagemaker-hyperpod-data-capture/)

## 3. coding agent model routing의 기준: token 가격이 아닌 solved task 비용

- **핵심:** LiteLLM과 NVIDIA NeMo Switchyard를 이용해 coding request를 여러 Bedrock 모델에 route하고 단일 모델 baseline과 비교하는 패턴이 공개됐다.
- **왜 중요한가:** 저렴한 모델이 더 많은 재시도와 긴 trajectory를 만들면 최종 task 비용과 완료 시간이 더 커질 수 있다.
- **바로 해볼 것:** repository task를 난이도별로 나누고 success, wall-clock, input/output/cache token, tool-call 수, retry, reviewer 수정량을 기록한다. routing objective는 `총 비용 / 해결된 task`와 SLA 위반률로 둔다.
- **원문:** [AWS — Route coding agents with NVIDIA NeMo Switchyard](https://aws.amazon.com/blogs/machine-learning/category/learning-levels/advanced-300/)

## 4. IAM principal 단위 AI 비용 귀속과 제한

- **핵심:** Bedrock inference call을 IAM principal과 session tag에 연결하고 CUR 2.0으로 사용자·팀·프로젝트별 비용을 계산하며 사용량 한도를 적용하는 패턴이 공개됐다.
- **왜 중요한가:** coding assistant와 productivity agent는 공유 API key를 사용하면 누가 어떤 model·workflow로 비용을 발생시켰는지 추적하기 어렵다.
- **바로 해볼 것:** 장기 공유 key 대신 SSO 기반 단기 credential을 사용하고 cost-center·project·environment tag를 session에 전파한다. warning threshold와 hard cap을 구분하고, 차단 시 저비용 모델 fallback 또는 read-only mode를 제공한다.
- **원문:** [AWS — Cost attribution and controls for AI developer tools](https://aws.amazon.com/blogs/machine-learning/category/learning-levels/advanced-300/)

## 5. Spot GPU 기반 speech inference의 interruption-tolerant 설계

- **핵심:** AssemblyAI는 On-Demand baseline과 다양한 GPU family의 Spot capacity를 혼합하고 SQS 기반 retry로 2분 회수 경고를 흡수한다.
- **왜 중요한가:** 대규모 음성 inference는 GPU 비용이 크지만, job queue와 실행을 분리하면 Spot 중단을 사용자 SLA와 분리할 수 있다.
- **바로 해볼 것:** job을 idempotent하게 만들고 visibility timeout, checkpoint 또는 clean retry를 적용한다. 여러 GPU family·AZ로 분산하고 On-Demand capacity로 최소 처리량을 보장한다.
- **데이터 경계:** 규제 산업의 audio는 regional queue, storage와 compute를 사용하고 재시도 과정에서도 region을 벗어나지 않도록 한다.
- **원문:** [AWS — Cost-optimizing AssemblyAI inference with EC2 Spot](https://aws.amazon.com/blogs/machine-learning/cost-optimizing-assemblyai-speech-to-text-inference-on-aws-with-amazon-ec2-spot/)

## 6. agent가 복구하고 재발 방지 PR을 제안하는 self-healing ETL

- **핵심:** Glue pipeline의 schema drift·missing field·type mismatch를 agent가 triage하고 데이터를 수정하며, 필요하면 upstream code 수정 PR을 제안하는 구조가 소개됐다.
- **왜 중요한가:** 자동 복구가 단순 재시도에 머물지 않고 incident evidence를 코드 변경으로 연결하는 운영 loop로 확장된다.
- **바로 해볼 것:** data repair와 code change 권한을 분리한다. agent는 quarantine dataset에서 수정안을 만들고 deterministic validation과 approval을 통과한 뒤만 production에 반영한다. 원본 데이터와 수정 provenance는 보존한다.
- **주의:** 자동 수정이 오류를 숨기지 않도록 repair rate, 반복 schema failure, downstream reconciliation을 지속 감시한다.
- **원문:** [AWS — Self-healing ETL with AgentCore](https://aws.amazon.com/blogs/big-data/build-a-self-healing-etl-pipeline-with-amazon-bedrock-agentcore/)

## 7. OpenFold3-preview를 관리형 비동기 inference로 배포

- **핵심:** SageMaker JumpStart에서 protein·DNA·RNA·ligand complex의 3D 구조를 예측하는 OpenFold3-preview를 자체 AWS 계정에 배포할 수 있다.
- **왜 중요한가:** 생물정보학 workload의 비동기 inference, multi-GPU parallelism, 자체 MSA 사용과 scale-to-zero 패턴을 관리형 경로로 검증할 수 있다.
- **바로 해볼 것:** 공개 benchmark만 보지 말고 내부 target class별 accuracy, runtime, GPU-hour와 실패율을 측정한다. 민감한 sequence·MSA는 접근 제어된 bucket에 두고 job별 output prefix와 retention을 적용한다.
- **원문:** [AWS — OpenFold3 on SageMaker JumpStart](https://aws.amazon.com/blogs/machine-learning/category/learning-levels/advanced-300/)
