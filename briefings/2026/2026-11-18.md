## 1. 에이전트 책임 있는 AI를 3단계 운영 체계로 전환

- **핵심 요약:** AWS는 에이전트 거버넌스를 ‘기반 구축 → 파일럿 검증 → 지속 평가·강화’로 나누고, 플랫폼 팀과 애플리케이션 팀의 책임을 구분했습니다. 모델뿐 아니라 도구, 데이터, 권한, 다단계 행동까지 평가 범위에 포함합니다.
- **AI 엔지니어에게 중요한 이유:** 에이전트 오류는 downstream 서비스로 전파되므로 단일 모델 평가만으로 안전성을 설명하기 어렵습니다. 배포 게이트, 최소 권한, 인간 검토, 드리프트 탐지가 하나의 운영 루프여야 합니다.
- **바로 확인하거나 실습할 항목:** 에이전트별 위험 등급·허용 도구·데이터 범위·인간 개입 조건을 등록하고, 프롬프트·모델·도구 변경 시 평가셋과 증적을 자동 재실행하세요.
- **원문:** [Responsible AI for agentic AI](https://aws.amazon.com/blogs/machine-learning/responsible-ai-for-agentic-ai-a-phased-roadmap-for-platform-and-application-teams/)

## 2. AWS Agent Registry에 조직 공통 메타데이터 스키마 도입

- **핵심 요약:** 에이전트, MCP 서버, 스킬 레코드에 사업부, 소유자, 위험 등급, 개발 환경 같은 조직 정의 필드를 강제할 수 있는 custom metadata schema가 추가됐습니다.
- **AI 엔지니어에게 중요한 이유:** 에이전트 수가 늘면 이름과 설명만으로 승인·검색·폐기를 관리할 수 없습니다. 공통 스키마는 소유권과 위험 분류를 레지스트리 단계에서 검증하는 기반입니다.
- **바로 확인하거나 실습할 항목:** `owner`, `risk_tier`, `environment`, `data_classification`, `review_due`를 필수 필드로 만들고, 승인되지 않은 고위험 레코드가 배포 파이프라인에 진입하지 못하게 하세요.
- **원문:** [Govern and discover records with common metadata](https://aws.amazon.com/blogs/machine-learning/govern-and-discover-records-with-common-metadata-in-aws-agent-registry/)

## 3. Snowflake MCP 연결에서 OAuth 패턴을 사용자·서비스 단위로 분리

- **핵심 요약:** AgentCore Gateway와 Snowflake 관리형 MCP 서버 사이의 인증을 Snowflake OAuth, 외부 IdP 기반 3-legged OAuth, 서비스 계정용 2-legged OAuth로 비교했습니다. OBO 토큰 교환은 비대화형 작업에서도 사용자 신원을 유지하는 선택지입니다.
- **AI 엔지니어에게 중요한 이유:** 단순한 client credentials는 운영하기 쉽지만 모든 요청이 하나의 서비스 사용자로 기록되어 사용자별 감사와 권한 분리가 사라집니다.
- **바로 확인하거나 실습할 항목:** 대화형 요청은 사용자별 3LO/OBO, 배치 작업은 최소 권한 2LO로 분리하고, Snowflake `QUERY_HISTORY`에 실제 기대한 주체·역할이 남는지 검증하세요.
- **원문:** [Secure OAuth patterns for Snowflake Cortex AI](https://aws.amazon.com/blogs/machine-learning/secure-oauth-patterns-for-snowflake-cortex-ai-through-amazon-bedrock-agentcore/)

## 6. 프롬프트 캐싱은 크기보다 재사용률이 중요

- **핵심 요약:** ArisGlobal은 요청마다 바뀌는 큰 문서 대신 모든 테넌트가 반복 사용하는 공유 프롬프트 접두부를 캐시해 유효 입력 비용을 약 50%, 월간 추론비를 약 40% 줄였다고 보고했습니다.
- **AI 엔지니어에게 중요한 이유:** 가장 큰 블록을 캐시하는 직관보다 얼마나 자주 동일하게 재사용되는지가 비용 효율을 좌우합니다. 멀티테넌트 규정·도구 정의·시스템 지침이 좋은 후보입니다.
- **바로 확인하거나 실습할 항목:** 프롬프트 구간별 토큰 수, 변경 빈도, 캐시 hit, 쓰기·읽기 비용을 기록하고 ‘절감액 = 재사용 횟수 × 회피 입력 비용 − 캐시 쓰기 비용’으로 비교하세요.
- **원문:** [How ArisGlobal scaled generative AI inference](https://aws.amazon.com/blogs/machine-learning/how-arisglobal-scaled-generative-ai-inference-on-amazon-bedrock/)

- **바로 확인하거나 실습할 항목:** 대표 시계열 질문으로 범용 LLM 기준선과 정확도·지연·비용을 비교하고, 예측 시점 이후 데이터 누출을 막는 시간 기준 train/test split을 적용하세요.
