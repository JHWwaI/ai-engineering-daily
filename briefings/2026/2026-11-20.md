## 1. OpenAI, Codex 기반 ‘Performance Factory’ 공개

**핵심 요약**  
OpenAI는 ChatGPT 성능 회귀를 자동으로 조사하고 수정하는 Performance Factory를 공개했습니다. 경보가 발생하면 에이전트가 원인을 조사하고, 별도 에이전트가 진단을 반박·검증한 뒤 수정 PR을 제안합니다. 엔지니어의 검토와 배포가 끝나면 다시 에이전트가 지표 회복 여부를 확인합니다. 3개월여 동안 1,700건이 넘는 조사를 추적하고 600건 이상의 근본 원인을 찾았다고 밝혔습니다.

**AI 엔지니어에게 중요한 이유**  
단일 장기 실행 에이전트보다 상태가 명시된 워크플로, 작업 외부의 영속 상태, 이벤트 기반 재개, 역할을 분리한 적대적 검토가 프로덕션 에이전트의 신뢰성을 높인다는 구체적인 운영 사례입니다. 특히 과거 장애를 재현하는 백테스트와 에이전트-엔지니어 인수인계 품질을 별도로 평가하는 방식이 실무에 바로 적용 가능합니다.

**바로 확인하거나 실습할 항목**

- 장애 대응 흐름을 ‘탐지 → 원인 분석 → 반박 검토 → 수정 → 사람 승인 → 회복 검증’ 상태 머신으로 모델링합니다.
- 과거 장애 10건으로 진단 정확도, 증거의 충분성, 요약 품질을 분리해 평가합니다.
- PR 리뷰·CI·배포 완료 이벤트가 에이전트를 다시 깨우도록 폴링 대신 구독 구조를 시험합니다.
- 도구 오류와 권한 실패를 매일 집계해 에이전트 자체의 운영 지표로 만듭니다.

## 2. SageMaker HyperPod, GPU 학습 인프라 관측성 강화

**핵심 요약**  
AWS는 EKS와 Slurm에서 실행되는 SageMaker HyperPod 학습 워크로드에 강화된 인프라 관측성을 발표했습니다. 분산 학습 처리량 저하가 GPU 스로틀링, 네트워크 포화, 호스트 데이터 파이프라인 정체 중 어디에서 발생했는지 진단하는 데 초점을 둡니다. HyperPod 지원 리전에서 제공됩니다.

**AI 엔지니어에게 중요한 이유**  
대규모 학습은 단일 비정상 가속기가 전체 작업을 멈추게 할 수 있고, 장애 탐지보다 원인 위치를 좁히는 시간이 더 큰 비용이 됩니다. 모델·프레임워크 로그와 하드웨어·네트워크 신호를 연결해 보는 관측 체계가 학습 클러스터의 MTTR과 낭비되는 GPU 시간을 직접 줄입니다.

**바로 확인하거나 실습할 항목**

- 학습 처리량과 함께 GPU 사용률·메모리·온도·스로틀링, 네트워크, 호스트 I/O를 동일 타임라인에 배치합니다.
- 정상 실행의 기준선을 저장하고 노드별 편차 및 straggler 탐지를 경보 조건에 넣습니다.
- 의도적으로 느린 데이터 로더나 통신 병목을 주입해 진단 화면이 원인을 구분하는지 검증합니다.
- 장애당 손실 GPU-시간과 평균 복구 시간을 운영 KPI로 추가합니다.

## 3. PolyAI Dialog-RSN-1, SageMaker JumpStart에서 제공

**핵심 요약**  
실시간 복합 대화를 위한 음성 추론 모델 Dialog-RSN-1이 AWS Marketplace와 SageMaker JumpStart에 추가됐습니다. 오디오를 직접 받아 인식·추론·응답하고 OpenAI Realtime 프로토콜을 사용합니다. 엔드포인트는 고객 AWS 계정의 VPC와 IAM 통제 아래 배포되며 현재 영어, 최대 30분 연결, 16/24kHz 16-bit PCM mono 입력을 지원합니다.

**AI 엔지니어에게 중요한 이유**  
음성 에이전트에서 STT, LLM, 턴 감지, TTS를 나눈 파이프라인은 지연과 오류 전파가 커질 수 있습니다. 단일 실시간 모델과 기존 보안 경계 내 배포는 콜센터·상담 시스템의 지연, 데이터 거버넌스, 운영 복잡도를 함께 비교할 새로운 선택지를 제공합니다. 다만 공급사 주장만 따르지 말고 실제 통화 데이터로 품질과 비용을 검증해야 합니다.

**바로 확인하거나 실습할 항목**

- 기존 Realtime 클라이언트의 base URL만 변경해 호환성, barge-in, 턴 종료 판단을 시험합니다.
- 억양·잡음·중단 발화가 포함된 자체 평가 세트로 응답 지연, 과도한 끼어들기, 업무 완료율을 측정합니다.
- VPC 흐름 로그, IAM 최소 권한, CloudWatch 로그의 민감정보 마스킹을 점검합니다.
- STT+LLM+TTS 분리형 구조와 종단 지연·분당 비용·감사 가능성을 비교합니다.
